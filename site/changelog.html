B Being drawn

Milestone 4: manifests from traffic alone.

Build a manifest for an undocumented API from what it actually sends, and score the result against a spec the agent never saw.

Capture inputsHAR, proxy, SDK logs

A HAR import, a recording proxy developers route through, or SDK request logs. Secrets are redacted at ingest.

Endpoint clusteringBy method and path pattern

Samples are grouped, and path variables are inferred from the segments that vary.

Schema inferencePer-field confidence

Response bodies merge into a JSON Schema with sample counts. Fields seen in every sample become required; the rest optional and nullable.

Probing policyGET and HEAD only

Only on endpoints already observed, rate limited, never on internal APIs without an explicit allowlist.

BenchmarkScore against a hidden spec

The ingester runs on a documented API with the spec hidden; inferred endpoints, fields, types and required flags are scored against it.

Exit criterionNot yet met

An inferred BambooHR manifest from traffic alone reaches an agreed score, and confidence correlates with correctness.

The discovery module (capture, clustering, inference, mapping proposals) exists in the repository and is not yet covered by the test suite.

C Designed

Flows, then codebases.

Two milestones are designed on paper: moving canonical objects between integrations, and treating a folder of code as a third discovery source.

Milestone 5: flows

Flow definitionSource to destination

A source connection and endpoint, a canonical object, a destination, a schedule and a filter. Manifests gain write endpoints with request mappings.

RunnerRead, map, dedupe, write

Scheduled or event-triggered, through the gateway both ways, with per-run counts of read, written and failed records.

Event bus and watchersAgents subscribe

Flow and drift events are published; agents alert on failed writes, hold a flow when its source has open drift, or summarize a run. Their tools are the gateway and the registry, exposed as MCP servers.

Exit criterionOne schedule tick

An Employee created in the source appears in the destination within one tick; simulated drift on the source pauses the flow and opens a change request.

Milestone 6: codebase integrations

Discovery sourceCode, after specs and traffic

The platform reads a folder, produces a manifest for the API that code serves, and observes its live traffic through the same loop.

ExtractionDeterministic first, agent second

Frameworks that describe themselves are converted exactly; an AST pass covers the rest; the agent fills only what is left blank, with confidence and source lines.

Lockfile, ledger, tapObserve-only by default

A lockfile pins manifest version to commit, a call ledger records every exchange's metadata, and a tap mirrors inbound traffic asynchronously.

Exit criterionScored against hidden OpenAPI

The extractor scores against this repo's own backend; tapped calls appear in the ledger with trace ids; a renamed route opens a change request before any traffic shows it.

D Decisions

Decisions that hold.

Made while building, written down so later work does not relitigate them.

Manifest first
Integrations are declarative data interpreted by a generic runtime. Sandboxed generated code is the escape hatch, not the default.
Triage is deterministic
Rules assign class and risk because risk gates approval, so the outcome has to be reproducible. The model only proposes patches.
Repairs are verified against reality
Against the live connection or a drift world pinned to the published manifest, never against a mock built from the candidate's own schema.
Incidents aggregate
One incident per integration, endpoint and kind while a human holds it, so new evidence lands on the open incident.
Approval on for everything
Every repair waits for a person until a risk class is unlocked per integration. Canary and rollback stay on either way.
Consent is human, refresh is autonomous
A person approves the scope screen; token refresh and re-consent detection run on their own; every credential event is audited.
