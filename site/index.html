A Overview

The API changed overnight. A verified patch is waiting for you.

An agent writes the integration as a manifest. A gateway validates every call. When the API changes, a verified repair waits for your approval.

    B Manifest

    An integration is a document, not a codebase.

    Auth, endpoints, schemas, pagination, mappings: one versioned manifest that a generic runtime interprets. Every change is a reviewable diff.

    name: bamboohr
version: 0.1.1
base_url: "https://api.bamboohr.com/api/gateway.php/{company_domain}/v1"
config_vars: [company_domain]
auth:
  type: basic
  username_secret_ref: api_key
  password_literal: x
rate_limit: { requests_per_second: 5, burst: 10 }
retry: { max_attempts: 3, backoff_seconds: 0.5, retry_on_status: [429, 502, 503] }
endpoints:
  - id: list_employees
    method: GET
    path: /employees/directory
    items_path: employees
    response_schema:
      type: object
      required: [employees]
      properties:
        employees:
          type: array
          items:
            type: object
            required: [id, displayName]
            properties:
              id: { type: string }
              displayName: { type: [string, "null"] }
              work_email: { type: [string, "null"], format: email }
              jobTitle: { type: [string, "null"] }
mappings:
  - endpoint_id: list_employees
    canonical_object: Employee
    fields:
      - { target: source_id, source: id }
      - { target: display_name, source: displayName }
      - { target: work_email, source: work_email }
      - { target: job_title, source: jobTitle }
      - { target: employment_status, transform: const, args: { value: active } }
    C The loop

    Discover, synthesize, verify, publish, watch, repair.

    One loop writes the first version and every repair after it. Each stage is described in full on the how it works sheet.

    1. Stage 1

      Discover

      Specs, docs, Postman collections or captured traffic.

    2. Stage 2

      Synthesize

      The agent drafts a manifest constrained to the schema.

    3. Stage 3

      Verify

      Every endpoint, on a mock and then live.

    4. Stage 4

      Publish

      Versioned and immutable. Rollback is one step.

    5. Stage 5

      Watch

      Validate responses. Watch status codes, headers, pagination.

    6. Stage 6

      Repair

      Triage, patch, verify, approval gate, canary, promote.

    A repair re-enters at Verify

    Rules assign class and risk. The model only proposes patches.

    Employeecanonical object

    Every source, one shape

    Each integration's mapping turns raw records into canonical Employee and Department objects. Consumers, human or agent, read one shape whatever the source.

    Identity
    source_id, display_name, first_name, last_name, work_email, personal_email
    Position
    job_title, department, division, location, manager_source_id, employment_status (active, on_leave, terminated, unknown)
    Dates, contact
    hire_date, termination_date, work_phone, mobile_phone
    Department
    source_id, name, parent_source_id
    See the model in the console

    Tenancy

    Each tenant's tokens sit in an encrypted vault under its own key. Refresh runs on its own. Consent never does: a person sees every scope and why. Every credential event is audited.
