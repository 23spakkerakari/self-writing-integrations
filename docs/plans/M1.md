# M1: Edge pipeline and offline analyzer

Status: built 2026-10-10 on branch `m1-edge-pipeline` (started 2026-10-08 from `m0-foundations`);
CI green. Acceptance waits on the founder: throughput on the reference node and the questions in
the demo note.
Spec: `docs/SPEC.md` Section 21, "M1: Edge pipeline and offline analyzer"; Sections 5.4, 7, 8,
12 (internal endpoints), 14.3, 14.4, 14.7, 18.1 to 18.3.

## Goal

The trusted edge exists end to end: every connector the spec names reads customer systems
read-only, the pipeline turns raw records into canonical events with no high-cardinality value
in clear, tokens are HMACs under a KMS-wrapped tenant key, raw values survive only in the
encrypted reveal vault at the edge, events reach core over mutual TLS through a disk buffer, and
`ingest-api` writes them to ClickHouse. The same pipeline packaged as `carto-edge analyze` turns
exported files into a signed bundle that core loads. The leak test (spec 18.3) is the arbiter.

## Decisions (ADRs 0011 to 0028, written with this milestone)

1. **Scenario B leak run waits for scenario B (ADR 0011).** Section 21 lists "Simulator
   scenario B" as an M4 deliverable and M1's acceptance names it; the two cannot both hold.
   The leak test is parametrized by scenario and runs on A now; B joins in M4. Flagged for the
   founder.
2. **KMS providers in M1: local file KMS and Vault Transit (ADR 0012).** The `KeyWrapper`
   protocol in `carto_common.crypto` admits AWS KMS, Azure Key Vault and GCP KMS wrappers; they
   arrive with the first partner that needs them (M6 at the latest).
3. **Edge secret resolution (ADR 0013).** `vault://` resolves against Vault KV v2 with a token
   read from a file; `local://` resolves against a KMS-wrapped SQLite store under the edge
   state directory (the spec's "stored in PostgreSQL" applies to core, which the edge cannot
   reach). `aws-sm://`, `azure-kv://`, `gcp-sm://` fail with a clear message until M6.
4. **SQLite in WAL mode for the disk buffer, the reveal vault and the cursor store (ADR 0014).**
   The spec allows it (8.5). The edge audit trail is a local hash-chained NDJSON file
   (`audit.ndjson`); core's audit log (M6) records the user-facing side of every reveal.
5. **Ingest idempotency by batch ledger (ADR 0015).** `events` and `event_identifiers` stay
   `MergeTree` exactly as in spec 7.2. `ingest-api` keeps `ingest_batches (tenant_id, batch_id)`
   in PostgreSQL: a batch already in the ledger is acknowledged and not rewritten. Order of
   operations: ledger lookup, ClickHouse insert, ledger insert, so a failed insert is retried and
   never lost. A race between two deliveries of one batch can write it twice; the linker counts
   distinct tokens, so that is harmless, and M2 may add `FINAL` where exactness matters.
6. **Templates and field refs (ADR 0016).** `template_id = "tpl_" + sha256(system_id + "\0" +
   template_text)[:12]`. Template text per kind: the Drain3 template of the message field for
   logs that have one; `keys:<sorted top-level keys>` for structured logs without a message;
   the root element name for XML; `row_change <query name>` for rows; `file_arrived <generalized
   file name>` (digit runs to `*`) for file events; `<METHOD> <generalized route> <status
   class>` for access logs; the configured event-type field, else the key signature, for
   webhooks. `field_ref = system_id/template_id/path`. Message parameters are fields
   `msg.param_0..n`; template-mined text records use `param_0..n`.
7. **Offline analyzer is two-pass (ADR 0017).** Pass 1 reads every input and feeds field stats
   and templates; pass 2 classifies with full statistics and emits events, so one bundle has one
   consistent classification and the manifest can list kept fields with sample values. The
   gateway streams with the spec's quarantine rule (unknown fields are tokenized when
   identifier-shaped, dropped otherwise, until 200 samples exist; re-classification is logged).
8. **SSRF pinning (ADR 0018).** `carto_edge.net.ssrf` resolves and validates every connector
   host (loopback, link-local, metadata, unlisted private ranges rejected). HTTP clients pin the
   validated address through a custom `httpcore` network backend while TLS still verifies the
   host name; PostgreSQL pins with `hostaddr`; SFTP connects to the validated address with the
   pinned host key. MySQL and SQL Server validate at each connect and connect by name.
9. **SQL Server is implemented, tested against a fake connection, not a container (ADR 0019).**
   PostgreSQL and MySQL read-only tests run under testcontainers; the SQL Server image and ODBC
   driver are too heavy for CI now and are scheduled for the payer partner's install.
10. **Presidio with an explicit recognizer registry (ADR 0020).** No URL recognizer (its
    `tldextract` dependency fetches the public suffix list from the internet, which breaks spec
    2.3 invariant 4); spaCy `en_core_web_sm` pinned by URL in the lockfile; Presidio runs on
    field samples and template constants, never on every value.
11. **Double Metaphone from the `metaphone` package (ADR 0021).** BSD, pure Python, the only
    maintained-enough implementation on PyPI; the algorithm is fixed, so age is not risk.
12. **Bundle signature (ADR 0022).** Ed25519 key generated per `analyze` run; the public key is
    in `signature.json`; the signature covers `manifest.json`, which carries every data file's
    sha256. Integrity, not origin.
13. **Internal assertions** (spec 8.4) are Ed25519-signed JSON (`carto_common.crypto`
    `InternalAssertion`): subject, permission, purpose, audience, issued/expires (at most 5
    minutes), nonce. The edge verifies with core's public key, enforces single use per nonce
    and the per-user reveal rate limit, and audits every call. The core API that signs them is
    M3; M1 ships the signer so M3 cannot diverge.
14. **Locator map file (ADR 0024).** `--locator-map` writes `<out>.locator_map.ndjson` next to
    the bundle directory (`sim-out/shop.carto.locator_map.ndjson`), one `{"key", "event_id"}`
    object per emitted event; never inside the bundle, never to core.
15. **Analyzer key material (ADR 0025).** `carto-edge analyze` creates a local-KMS tenant key
    under `--state-dir` on first run (the `carto-ctl key init --kms local` layout) and reuses it
    afterwards, so re-runs over the same state directory produce the same tokens and template
    ids; the bundle never carries the key or the vault.
16. **Batch keys are pinned (ADR 0026).** `manifest_id`, the shipping `file` and the file-drop
    `name` are pinned as identifiers in the scenario configs; a default safeguard for
    low-cardinality identifiers is a founder question.
17. **Values never travel as names, one-off templates or rare kept values (ADR 0027).** Value-like
    name segments are masked, CSV headers and logfmt flags are validated, a Drain3 template needs
    three members, and a kept value needs three exact sightings. Map keys without digits remain
    a residual risk for the founder.
18. **Throughput is judged on the full gateway path (ADR 0028).** `make bench-gateway` runs the
    buffer, cursors and forwarder too; several pipeline workers come only if it falls short.

## Wave 2 seams (fixed before D1, D2 and D3 started, 2026-10-09)

Wave 1 left `pipeline/pipeline.py` and `pipeline/buffer.py` done; the rest of D and the install
docs of G were split three ways. The seams below are code, not prose: `carto_edge.runtime`,
`carto_edge.pipeline.ingestor` and `carto_edge.metrics` exist, and the settings they need
(`core.batch_flush_seconds`, `core.retry_max_seconds`, `gateway.poll_seconds`,
`gateway.stats_flush_seconds`) are in `carto_edge.config`.

- **`carto_edge.runtime`** (done): `EdgeRuntime` (settings, sources, `keys: KeyManager`,
  `keyring`, `tokenizer`, `vault`, `detector`, `stats`, `templates`, `classifier`, `pipeline`,
  `audit`; `tenant_id`, `key_versions`, `policy_version`, `write_vault_entries(results)`,
  `flush()`, `close()`), `build_runtime(settings, sources, mode="gateway"|"analyze", clock=,
  detector=, init_local_keys=)`, `build_reveal_service(runtime)`,
  `build_connector_context(runtime)`. `analyze` mode sets `quarantine_samples=1`, keeps
  statistics in memory and runs the pipeline with `observe_on_process=False` (ADR 0017); the
  analyzer calls `pipeline.observe_only` over every record first.
- **`carto_edge.pipeline.ingestor`** (done): `IngestorLike` protocol (`ingest(records) ->
  IngestOutcome`, `flush() -> int`, `backpressure() -> BackpressureState` with `OK`, `SLOW`,
  `FULL`), `IngestOutcome` counters. Receivers depend on the protocol only.
- **`carto_edge.metrics`** (done): `EdgeMetrics` registry (`counter`, `gauge`, `inc`, `set`,
  `get`, `render`) and `default_metrics()` declaring the `carto_edge_*` series; one registry
  per process, handed to the ingestor, the forwarder, the scheduler and the app.
- **D1, `carto_edge.pipeline.batch`:** `BatchAccumulator(tenant_id, source_id, *, max_events,
  max_bytes, clock)` with `add(event) -> IngestBatch | None` (returns the sealed batch when the
  event count or the serialized size would exceed the limits), `seal() -> IngestBatch | None`,
  `pending`, `age_seconds(now)`; `Ingestor(runtime, buffer, cursors, *, link: CoreLinkSettings,
  metrics, clock)` implementing `IngestorLike`: pipeline, vault write, per-source accumulators,
  `buffer.append`, then `cursors.set(source_id, cursor)` with the last `commit_cursor` among the
  records whose events are now durably buffered (records whose events are still in a partial
  batch do not advance the cursor); `flush_stale(now)` seals batches older than
  `batch_flush_seconds`. Records of a source the sources file does not know are dropped with
  reason `unknown_source` and never appended.
- **D1, `carto_edge.state`:** `CursorStore(path)` over `cursors.sqlite` (ADR 0014): `get(source_id)
  -> Cursor | None`, `set(source_id, cursor)`, `all()`, `close()`; cursors are JSON, bounded.
- **D1, `carto_edge.pipeline.forward`:** `build_core_client(link: CoreLinkSettings) ->
  httpx.Client` (mTLS from `ca_file`, `cert_file`, `key_file`; TLS 1.2 minimum; `trust_env=False`;
  no redirects); `Forwarder(buffer, client, *, metrics, clock, sleep, retry_max_seconds)` with
  `send_once() -> SendReport` (oldest pending batch: `POST /internal/ingest` with
  `Content-Encoding: zstd` and the stored payload; 2xx acks the row; 400, 403, 413, 415, 422
  park it; 429, 5xx and transport errors back off with jitter up to `retry_max_seconds`) and
  `run(stop: threading.Event)`; `SourceHealth` tracker (`record_read(source_id, records,
  lag_seconds, at)`, `record_error(source_id)`, `snapshot()`) and `Heartbeater(client, tenant_id,
  sources, buffer, health, *, metrics, clock)` posting one `SourceHeartbeat` per enabled source
  every `heartbeat_seconds` (`status` ok/degraded/failing from the error counts, `buffer_depth`,
  `oldest_buffered_at`). Nothing logs a body.
- **D1, `carto_edge.gateway.scheduler`:** `PollScheduler(runtime, ingestor, cursors, context,
  health, *, metrics, default_poll_seconds, clock)`: one asyncio task per enabled pull source
  (`upload`, `splunk`, `sql`, `sftp`; `otlp` and `webhook` are push), each loop `read(cursor)`,
  then `ingestor.ingest` in chunks, then `ingestor.flush()` at the end of a read, then sleep the
  connector's `poll_seconds` (config) or the default; pauses while `backpressure()` is not `OK`;
  a connector error counts in health and backs off with `carto_edge.net.retry`; `async def
  run(stop: asyncio.Event)` and `async def close()`.
- **D2, `carto_edge.gateway.otlp`:** `parse_logs_request(body, *, content_encoding, max_bytes,
  received_at) -> OtlpRecords` (records by `carto.source_id`, `rejected` count for records
  without one); protobuf `ExportLogsServiceRequest` only (`application/x-protobuf`), `gzip`
  and `zstd` content encodings with the decompressed size capped at `otlp_max_body_bytes`;
  body string to `RawRecord.text`, body key-value list to `fields`, log attributes other than
  `log.file.*` merged into `fields`; `kind` LOG; locator `otlp:<sha256(source_id, body bytes,
  time_unix_nano)[:16]>`; `received_at` now; the `ExportLogsServiceResponse` carries
  `partial_success.rejected_log_records`.
- **D2, `carto_edge.gateway.app`:** `create_gateway_app(settings, runtime, ingestor:
  IngestorLike, reveal: RevealService, metrics, *, ready: Callable[[], bool], clock)`:
  `POST /v1/logs` (OTLP; 429 when `SLOW`, 503 when `FULL`, 415 on another media type, 413 over
  the cap), `POST /webhooks/{source_id}` (body cap `webhook_max_body_bytes`, 404 unknown or
  non-webhook source, 401 bad or missing signature via the connector's `verify_signature` with
  the resolved secret, 400 on a bad body, same backpressure codes), `POST /internal/tokenize`
  and `POST /internal/reveal` (`RevealService`; 401, 413, 429 with `Retry-After`, 503 from its
  typed errors), `GET /healthz`, `GET /readyz`, `GET /metrics`. RFC 7807 problems that never
  echo input; `X-Request-Id` as in ingest-api; no docs routes; bodies never logged.
- **D2, `carto_edge.gateway.server`:** `run_gateway(settings) -> int`: load the sources file,
  `build_runtime(mode="gateway")`, `DiskBuffer`, `CursorStore`, `Ingestor`, `Forwarder` and

  (`gateway.tls_*`, client certificate required, TLS 1.2 floor, `log_config=None`), periodic

- **D3, `carto_edge.bundle`:** `BundleWriter(out_dir, *, tenant_id, producer, key_versions,

## Bundle format (spec 8.1.1) as built

```
bundle.carto/
  manifest.json       BundleManifest (bundle_version "1", bundle_id, tenant, producer, key versions,
                      policy_version, per-source counts, totals, sha256 and size of every data file)
  MANIFEST.md         human-readable: sources, counts, fields kept in clear with up to 5 sample values,
                      fields tokenized (shapes only), fields dropped, templates
  events.ndjson.zst   CanonicalEvent per line, zstd level 3
  fields.json         list[BundleField]
  templates.json      list[BundleTemplate]
  signature.json      BundleSignature: ed25519 over the exact bytes of manifest.json
locator_map.ndjson    eval mode only, written next to the bundle, never inside it (ADR 0006)
```

`carto-core load-bundle` verifies the signature and every digest before reading a single event,
then writes events in batches of 5,000 through the same ClickHouse writer as `ingest-api`, with
`batch_id = derive_ulid(created_at_ms, bundle_id, chunk index)` so a re-run is idempotent.

Built 2026-10-08 to 2026-10-10 on branch `m1-edge-pipeline` (Windows 11, Git Bash, uv-managed
CPython 3.12). Two waves of parallel implementers (Fable 5.1, then Opus 5.5 when those credits
ran out) built the connectors, pipeline, gateway, ingest-api, analyzer and guides against the
seams fixed above; the orchestrator integrated them, ran independent reviews (correctness,
security and leakage, spec compliance) and fixed every reproduced finding with a regression test.

Findings worth knowing about:

- Presidio was called once per value: 36 events/s. A per-value verdict cache fixed it.
- The first throughput figures, 1,100 to 1,800 events/s, were wrong. This laptop has 2 fast cores
  and 8 efficiency cores, and those runs were also throttled, most likely on battery. Pinned to one
  core, the same code runs three to five times faster (ADR 0028).
- `manifest_id` and the nightly file name are identifiers with one value per night, so spec 8.3
  rule 6 kept them in clear and the leak test caught them in ClickHouse (ADR 0026, pinned).
- The analyzer review found values leaving outside the classifier: in field names (JSON maps
  keyed by id, CSV rows read as headers, logfmt bare words), in one-off Drain3 templates, as rare
  values of kept fields, and as the analyst's directory path. All closed (ADR 0027); the leak
  test now plants a probe for each class and fails if any one comes back.
- Smaller ones: the row connectors ignored their actor column (the clerk login travelled as an
  attribute); push routes acknowledged before the events were durable; httpx logged full URLs
  at INFO; a reveal rejection path deadlocked on its own lock.
- CI-only: the core wheel shipped without its migration scripts, so `carto-core migrate` failed
  in the images and ClickHouse silently reported "up to date"; ClickHouse's init needed KILL;
  SFTP test URLs, the TLS floor default and MySQL 8.4 authentication differed on Linux.
