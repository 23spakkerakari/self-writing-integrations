A Install

Backend first, then the console.

The tests run offline against the mock provider. No credentials are needed for the first ten minutes.

Backend

cd backend
pip install -e ".[dev]"
python -m pytest

Import, verify, publish, call

The reference BambooHR manifest is the quickest first integration. The call goes to a mock built from the manifest's own response schemas.

python -m app.cli import manifests/bamboohr.yaml
python -m app.cli verify bamboohr 0.1.0
python -m app.cli publish bamboohr 0.1.0
python -m app.cli call bamboohr list_employees \
  --config company_domain=acme \
  --secret api_key=BAMBOOHR_API_KEY --mock

Drop --mock to hit the real BambooHR API once a key exists. Set ANTHROPIC_API_KEY and have the agent build the manifest from the spec instead of importing the reference one:

python -m app.cli synthesize \
  specs/bamboohr-employees.openapi.yaml --name bamboohr

Control plane

uvicorn app.main:app --reload
# OpenAPI UI at http://127.0.0.1:8000/docs

Set GATEWAY_MODE=mock to run against the offline provider, including the mock authorization server for OAuth flows.

Console

cd ../frontend
npm install
npm run dev
# http://127.0.0.1:5173, proxies /api to the backend
B CLI

The same loop from the terminal.

Every command runs as python -m app.cli from the backend folder.

CommandWhat it does
import <manifest.yaml>Stores a manifest file as a draft version of its integration.
synthesize <spec> --name <name>Has the agent write a manifest from a spec, verify it on the mock, and feed failures back for another round.
verify <name> <version>Runs every endpoint of a version against the spec-derived mock and stores the report.
publish <name> <version>Makes a verified version the published one. The previous published version is superseded.
call <name> <endpoint> --config k=v --secret k=ENV --mockCalls an endpoint through the gateway. Config values fill the base URL; secrets are environment variable names resolved server-side. --mock targets the mock.
vault-keyGenerates a master key for VAULT_MASTER_KEY.
incidentsLists drift incidents.
changesLists change requests.
approveApproves a change request.
rejectRejects a change request.
promotePromotes a change request, publishing its candidate version.
rollbackRe-publishes the previous version of an integration in one step.
policyReads or sets the per-risk-class approval policy of an integration.

D Environment

Twelve variables, all optional at first.

The defaults run offline. Credentials and the model key only matter once you leave mock mode.

E Manifest

The document the runtime reads.

A manifest is validated against a JSON Schema with cross-checks. Extra keys are rejected, so a typo cannot become a silent default.

Top-level keys

KeyMeaning
nameThe integration's identifier, such as bamboohr.
versionThe version string. Versions are immutable once stored.
display_nameWhat the console shows.
descriptionOne sentence on what the integration reads.
base_urlMay contain {variables} filled from a connection's config.
config_varsThe variables the base URL needs. Every variable used must be listed.
authOne of the auth types below.
default_headersSent on every call.
rate_limitrequests_per_second and burst, enforced by a token bucket.
retrymax_attempts, backoff_seconds and retry_on_status. Retry-After is honoured.
endpointsThe list of endpoints. Ids must be unique.
mappingsField-level mappings from an endpoint's records onto a canonical object.

Auth types

TypeKeys
noneNo credentials.
api_keylocation (header or query), name, prefix, secret_ref.
bearersecret_ref.
basicusername_secret_ref or username_literal, password_secret_ref or password_literal.
oauth2flow (authorization_code), authorization_url, token_url, scopes, scope_separator, pkce, token_auth_method (client_secret_post or client_secret_basic), refresh_leeway_seconds, extra_authorization_params.

A secret reference names a secret the connection supplies. The manifest never holds a secret value, and the gateway is the only component that resolves one.

Endpoint keys

KeyMeaning
idUnique within the manifest, such as list_employees.
methodGET, POST, PUT, PATCH or DELETE.
pathRelative to the base URL. Path parameters are written as {id} and must be declared.
descriptionWhat the endpoint returns.
parametersEach with name, location (path, query or header), required and description.
default_queryQuery parameters sent when the caller gives none.
default_headersHeaders for this endpoint only.
response_schemaThe JSON Schema every live response is validated against.
items_pathWhere the list of records sits in the body.
paginationstyle is none, page, offset or cursor, with page_param, size_param, page_size, offset_param, limit_param, cursor_param and next_cursor_path as the style needs.
scopesOAuth scopes this endpoint needs on top of the base scopes.

Mappings and transforms

A mapping names an endpoint_id, a canonical_object (Employee or Department) and a list of fields. Each field has a target, an optional source, an optional transform and its args.

TransformWhat it does
to_dateParses a date string into a date.
enum_mapMaps source values onto canonical ones through args.map, with args.default for anything else.
concatJoins several source values.
first_non_nullTakes the first source value that is present.
constSets a fixed value from args.value.
split_takeSplits a string and takes one part.
to_str and other coercionsCoerce a value to a type.

The registry is closed: a manifest can only name transforms from this list, so no arbitrary code ever enters one. Two rules apply to every mapping: source_id must always be mapped, and an Employee must carry at least one identity field, which is display name, work email, first name or last name.

F Console

Five pages and a tenant switcher.

The console runs against the control plane in mock or live mode and shows which in its sidebar.

  • Integrations. The registry, each integration's versions and their verification reports, endpoints, drift, approval policy and the call console.
  • Connections. Tenant connections, OAuth app registration, the consent screen and each connection's audit timeline.
  • Drift. Incidents and change requests, the approval gate, canary, promote, abort and the worker tick.
  • Activity. The audit log and notifications for the selected tenant.
  • Canonical model. Employee and Department, field by field.

The tenant switcher in the sidebar scopes connections, audit history and notifications to one tenant, and creates new tenants. The mode indicator beneath it reads Mock gateway or Live gateway from /health. In development, npm run dev proxies /api to the backend on port 8000, so the browser never deals with CORS.
