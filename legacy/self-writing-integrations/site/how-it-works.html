One loop, six stages, every version.

The same loop writes the first version of an integration and every repair after it. Each stage below says what it reads, what it produces, and what can stop it.

A Discover

Start from whatever the API gives you.

A spec, a docs page, a collection, or the traffic you already send. Each input is normalized to one internal spec before the agent sees it.

OpenAPI or GraphQL specBuilt

Imported as is and snapshotted with a content hash, so later re-fetches can be diffed.

Docs URLBuilt

A documentation page is read and normalized the same way as a spec.

Postman collectionBuilt

Requests in a collection become candidate endpoints with their parameters.

Captured trafficMilestone 4, being built

HAR files, a recording proxy, or SDK request logs, with secrets redacted at ingest.

Code in a repositoryMilestone 6, designed

The API a folder of code serves, extracted deterministically first and by the agent second.

Active probing is limited to safe methods, GET and HEAD, only on endpoints already observed, rate limited, and never on internal APIs without an explicit allowlist.

B Synthesize

The agent drafts a manifest it cannot break.

Claude produces the manifest as structured output constrained to the manifest JSON Schema. What it writes is data, and the schema decides what data is allowed.

OutputStructured, schema-constrained

If the provider rejects the schema, the agent falls back to free-form JSON that is validated the same way.

FeedbackBounded attempts

Validation errors go back to the agent for a fixed number of tries. Extra keys are rejected outright.

Cross-checksFive rules

Unique endpoint ids, declared path parameters, known canonical targets, known transforms, and base URL variables listed in config vars.

Modelclaude-opus-5

The default, set with SYNTHESIS_MODEL. The same entry point repairs a manifest from verification feedback.

TransformWhat it does
to_dateParses a source value into a date, as for hire_date and termination_date.
enum_mapMaps source values onto canonical ones with a default, as Active and Inactive onto employment status.
concatJoins several source fields into one value.
first_non_nullTakes the first source field that carries a value.
constSets a fixed value, as employment_status active for a directory of active employees.
split_takeSplits a string and keeps one part.
to_str and other coercionsConverts a value to the type the canonical field expects, as a numeric manager id to a string.

The registry is closed. The agent chooses from these names and nothing else, so no arbitrary code enters a manifest.

C Verify

Checked on a mock, then checked for real.

The harness calls every endpoint of the manifest, first against a mock generated from the spec, then against a live account when one exists. Both produce the same report.

OrderList endpoints first

Ids harvested from list responses feed the detail endpoints, so get_employee is called with a real id.

GradesFour checks per endpoint

Status code, schema validation, mapping onto the canonical object, and identity completeness of the result.

Mock and liveSame report shape

A report from the mock reads the same as one from the real API, so the console shows both in one table.

On failureBack to synthesis

Failures feed back into the agent, up to a maximum number of rounds, before a version is stored as rejected.

D Publish

Versions are immutable. Rollback is one step.

A version moves through the registry and never changes once stored. Publishing supersedes the previous published version; rolling back re-publishes it.

draft verified published superseded or rejected or rolled_back

A version that fails verification is stored as rejected. A rolled back version is marked rolled_back and can never be published again.

Stored per versionManifest, report, provenance

The manifest JSON, its verification report, and where it came from: an import, a synthesis run, or a repair naming its incident.

Spec snapshotsContent hashed

Every fetched spec is kept with a hash, so a re-fetch can be diffed and a change opens an incident.

On publishPrevious version superseded

The gateway serves the published version by default; a caller may name another version to try a draft.

On rollbackOne step

The previous published version is re-published and the promoting change request is marked rolled back.

E Watch

Drift is noticed before users notice.

The gateway validates every live response instead of just executing calls. For an undocumented API there is no spec to re-fetch, so the response itself is the primary signal.

From the spec watcherspec_changed

A re-fetched spec is snapshotted and diffed; a difference opens an incident carrying the diff.

AggregationOne incident per endpoint and kind

Events fold into an incident while it is unresolved, so a second change on the same endpoint adds evidence instead of opening a parallel one.

F Repair

Triage by rules, patch by machine or agent, promote by consent.

Rules, not the model, assign the class and the risk, because risk decides how much supervision a repair gets. The model only proposes patches.

First attemptMechanical rename

Schema, items_path, cursor path and mapping sources are rewritten together before the agent is asked.

Second attemptRepair agent

Receives the incident, its samples, the sample body, the latest spec snapshot and class guidance. A verification failure buys one more round.

Change requestDiff aligned by identity

A reviewer reads a path like /mappings/[endpoint_id=list_employees]/fields/[target=display_name]/source, not a list index.

Approval policyPer integration, per risk class

Default off for every class. A policy that is on still verifies the candidate and runs a canary before promoting.

Canary verdictPass, fail, or insufficient

Pass once the candidate has CANARY_MIN_CALLS calls, a failure rate under 10% and is no worse than the base. Promote publishes; abort keeps the base live.

RollbackOne step

The version is marked rolled_back and can never be published again. Its incident goes back to a person.
